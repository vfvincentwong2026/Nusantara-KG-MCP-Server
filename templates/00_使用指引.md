# 知识数据 AI 生成 · 使用指引（P0 数据录入工作流）

> 目标：不手敲数据。用免费大模型（Kimi 网页版/App 均可）按模板批量生成知识节点，
> Owner 只校对关键数字，校对通过即入库。

---

## 一、四步工作流

```
① 复制模板提示词  →  ② 粘贴到免费模型，填入【主题】  →  ③ 校对数字  →  ④ 存盘提交
   (本目录 01-04)      (Kimi / 任何免费模型)              (只改带 ⚠️ 的字段)   (.md 文件)
```

### ① 复制模板
- `01_工艺节点生成提示词.md` —— 生成施工工艺（最高优先级）
- `02_工时定额生成提示词.md` —— 生成某工艺的工时定额
- `03_人工对比生成提示词.md` —— 生成人工等级档案
- `04_材料节点生成提示词.md` —— 生成材料档案

### ② 粘贴生成
打开 Kimi（免费）→ 新建对话 → 整段粘贴提示词 → 把开头的【主题】换成你要生成的工艺名
（如"微水泥墙面施工"）→ 发送。模型会输出一份完整 Markdown。

### ③ 校对（只做这一步，5 分钟/篇）
模型输出的正文中，所有**数字类字段**都带 ⚠️ 标记，你只需要：
- 核对工时 / 日薪 / 价格是否符合你在印尼的真实经验，不对就直接改；
- 核对验收标准的容差数值（如平整度 3mm/2m）；
- 描述性文字（工序步骤、避坑说明）不用逐字改，扫一眼没有常识错误即可；
- **粘贴前检查**：删掉从网页版带出的 `text` / `复制` / `下载` 残留行（2026-08 已踩坑清理过一批）；
- 校对完成后：删掉 ⚠️ 标记，并把 frontmatter 的 `status: draft` 改为 `verified`。

> ⚠️ 纪律：**数字不信 AI**。AI 生成的工序描述质量很高，但工时和价格
> 必须以你的实战数据为准——这正是这个知识库的护城河。

> 📐 数据契约：所有文件的 frontmatter / 章节结构以 `DATA_MODEL.md`（v2）为准；
> `relations[].target` 用裸 id，正文双链用 `[[id|显示名]]`。

### ④ 存盘提交
- 文件命名：`<英文名><中文名>.md`（如 `Wet Method Tiling湿铺法地砖铺贴.md`），按类型放入对应目录：
  - 工艺 → `obsidian-vault/05_Processes/`
  - 工时 → `obsidian-vault/07_WorkHours/`
  - 人工 → `obsidian-vault/06_Labor/`
  - 材料 → `obsidian-vault/04_Materials/`
- `git add . && git commit -m "data: add process XXX" && git push`

## 三、校对接口（给未来 P1 用）

生成的 .md 文件即最终数据源。后续 `npm run build` 会把它们编译成
`data/nodes.json + edges.json` 供服务调用——你不需要关心这一步，只管攒 .md。
